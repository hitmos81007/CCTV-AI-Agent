## Gaps against the submission and current requirements

The submission's architecture shows investigation intake, a central planner selecting cameras and assigning work, hybrid footage, parallel agents, evidence correlation, and a dashboard with map, candidate results and case report. Its scope slide specifies **six simulated jurisdictions** and a vehicle theft prototype. An earlier figure says three simulated zones. Use the explicit six-jurisdiction requirement for Phase 2. The figure's **12 recordings, four aggregate hours, and a first pass within 20 minutes** are benchmark targets. Judge them with separate measures for time to first lead, total search time, footage coverage, labeled precision and recall, review time, and evidence traceability.

| Target | Current implementation and missing work |
| --- | --- |
| Six jurisdictions and LangGraph | FastAPI case validation, the n8n intake/planner and the UI assume four compass directions. The manual trigger hardcodes a synthetic case and adjacency map. n8n planner objects with empty candidates and null hashes are status placeholders. Implement one configurable six-jurisdiction topology and a LangGraph planner that selects cameras/time windows, dispatches existing workers and records its decisions. Retain the n8n integration. |
| Hybrid CCTV sources | All inputs are file uploads with camera and recording-time labels. A saved police export and a private DVR export can both be uploaded today, but the catalog does not distinguish those sources. Add camera registration, source provenance and supported authorized police feed/archive adapters, including ONVIF/RTSP where applicable. Keep original evidence ingestion and hashing. |
| Parallel and bounded searches | FastAPI fans out tasks, but inference defaults to one slot per batch. Each call processes the full clip. Follow-ups choose an overlapping clip, yet the detector does not enforce the time window. Jobs use the active case clue rather than the initiating sighting snapshot. Vehicle candidates can enqueue additional jobs automatically. Add bounded processing, an immutable search context, duplicate protection, and job recovery. The per-batch limit alone does not protect the shared YOLO tracker across independent requests. |
| PaddleOCR, reference input and ranking | YOLO and the broad color rule provide basic filtering. Sedan is grouped under car. Passed results get score 1.0 and the list sorts by time. Add plate reading with explicit unreadable/uncertain outcomes, vehicle reference input, and ranking that explains the cues for each lead. Keep hard-to-verify observations available for human review. |
| PostgreSQL and evidence traceability | SQLite plus local file storage has demonstrated integrity and migration behavior. Add a PostgreSQL persistence path and rehearse migration against a copy with all legacy hash versions. Maintain source provenance and consistent review and follow-up history. Keep evidence blobs on an explicitly configured protected storage path. |
| Geographic map, movement trail and React | The current UI shows camera/zone labels and time without coordinates, a map, an across-camera vehicle trail or an evidence report. Add a camera catalog with coordinates and source metadata, show candidate sequences as hypotheses with supporting stills, and make the officer's verification state visible. Port the existing dashboard flows to React before expanding them. |
| Demo and measurement | The existing files and isolated controls verify the application pipeline. Twelve upload rows represent two unique videos. Establish a labeled vehicle-theft demo with distinct camera views and expected leads, then measure the stated benchmark independently. |

## Phase 2 starting order

1. Keep the existing FastAPI contracts and local data as compatibility references. Resolve the legacy review regression and verify it against an isolated migrated copy. Capture the baseline contract results before changing the planner.
2. Use one configurable camera and jurisdiction registry for FastAPI, LangGraph, n8n and React. Prove six named jurisdictions through the same intake and run path, with observable camera selection and bounded clip windows.
3. Validate a vehicle-theft path on authorized demo inputs. Use the file-ingest path for collected DVR footage and add a police feed/archive adapter. Return ranked timestamped JPEG leads, camera locations, a proposed vehicle trail, audit hashes and reviewer decisions. Exercise OCR uncertainty and source provenance explicitly.
4. Run the React-to-FastAPI flow and PostgreSQL migration with isolated data. Recheck live n8n after the Docker engine is available. Measure the defined benchmark against labeled recordings and publish measured values separately from targets.
